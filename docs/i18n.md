# Interface translations

The frontend currently supports English (`en`) and Spanish (`es`). Messages
live in `frontend/messages/en.json` and `frontend/messages/es.json`; their
object paths must match exactly. CI checks this with
`npm run check:i18n` from `frontend/`.

## Add or change a string

1. Add a descriptive key to both locale JSON files in the same location.
2. Translate the Spanish value rather than copying the English text.
3. In the component, call `useTranslations('<namespace>')` and render the value
   with `t('<key>')`. Pass dynamic values as named interpolation parameters.
4. For locale-sensitive values, use the active locale with
   `Intl.NumberFormat(locale, options)` or `Intl.DateTimeFormat(locale,
   options)`. Avoid hardcoding `en-US` or relying on the host default.
5. Run `npm run check:i18n` from `frontend/`.

## Add a language

Add the locale code to `SUPPORTED_LOCALES` in `frontend/lib/locale.ts`, add its
label in `LOCALE_LABELS` and import/register its complete message file in
`frontend/lib/i18n.ts`. Create `frontend/messages/<locale>.json` with the same
key structure as English, then translate every value and update the parity
check script to include the new locale. Check date, number, and currency
formatting in the newly supported locale.
